# VOICEVOX 読み・アクセント事故ゼロ運用マニュアル

> **このマニュアルの内容は、すべて OpenJTalk 実機の出力で検証済みです。**
> VOICEVOXのG2Pは `OpenJTalk + naist-jdic`。同じものをローカルで動かし、
> 発音とアクセント型を実測した結果だけを載せています。
>
> ```
> apt-get install -y open-jtalk open-jtalk-mecab-naist-jdic hts-voice-nitech-jp-atr503-m001 mecab
> python3 njd_check.py 台本.md        # 読み・アクセント句
> python3 homograph_check.py 台本.md  # 同表記異読語を辞書側から全数列挙
> python3 telop_wrap.py 台本.md --check   # テロップに収まらない文
> ```

## 検出方法 —— 語を思いつくのではなく、辞書から引く

過去版の最大の失敗は「危なそうな語」を頭の中のリストから探していたことです。
その方式では必ず漏れます。正しい手順はこれです。

1. 台本を OpenJTalk に通し、**実際に選ばれた発音**を得る
2. 各表層形を naist-jdic に単独で引き、**登録されている読みを全部**取る(`mecab -a`)
3. 読みが2通り以上ある語を「要目視」として、採用値と候補を並べて出す

`homograph_check.py` がこれをやります。現行台本では **145種** が該当し、全件を
文脈と照合して誤りゼロを確認しました。例:

```
■ 金  →  採用「カネ」   他候補: キン / ガネ / カナ / コン / キム
■ 方  →  採用「カタ」   他候補: ホー / ポー / ガタ
■ 筋  →  採用「スジ」   他候補: キン
```

「金」に6通り、「方」に4通りが辞書登録されています。**単独の漢字1〜2文字の和語が
最も危険**なのは、候補が多いからです。

## アクセント —— 本当の問題は「アクセント句の分割」

現行台本を実機にかけると、**固有名詞が複数のアクセント句に割れています**。

```
鷹野物産 (3箇所)  中村結衣 (2箇所)  神崎涼介 (2箇所)
中村健一 (1箇所)  神崎政子 (1箇所)  鷹野誠一 (1箇所)
```

読みは正しい。**問題はアクセントです。**
2句に割れると「タカノ↗ ブッサン↗」と音程が2回上がり、人名を呼ぶたびに素人くさく聞こえます。

**辞書に1語として登録すると、1アクセント句にまとまって解消します。**
つまり辞書登録は「読みを直すため」ではなく、**アクセントを直すため**にやります。

なお `東洋通商` `みやこ食堂` `日替わり定食` は**分割されていません**(実機確認済み)。
登録は不要です。

### 辞書登録リスト(VOICEVOX → 設定 → 読み方&アクセント辞書)

入力は「単語 / 読み(全角カタカナ) / アクセント核 / 優先度」。核 `0` = 平板。

| 単語 | 読み | 核 | 優先度 |
|---|---|---|---|
| 中村結衣 | ナカムラユイ | 0 | 9 |
| 中村健一 | ナカムラケンイチ | 0 | 9 |
| 神崎涼介 | カンザキリョースケ | 0 | 9 |
| 神崎政子 | カンザキマサコ | 0 | 9 |
| 鷹野誠一 | タカノセーイチ | 0 | 9 |
| 鷹野物産 | タカノブッサン | 0 | 9 |

> 長音は必ず **`ー`** で登録する(`セイイチ` ではなく `セーイチ`)。
> `イ` で登録すると母音が二拍に割れて不自然になります。

### 長すぎるアクセント句

13モーラを超えるアクセント句は、区切りが不自然になります。
`njd_check.py` の ④ で検出されるので、**読点を1つ入れて割ってください**。

例) `鷹野物産の代表取締役会長です` (17モーラ) → `鷹野物産の代表取締役、会長です`

### 最後は必ず耳で

アクセント型は実機で取れますが、**自然さの最終判断は人間の耳にしかできません**。
エディタで全文を流し込み、アクセント句の区切り線を上から目で追い、**通しで聴いてください**。

## 三稿で見つかった事故 —— 「検査器が通った」は「事故が無い」ではない

台本01〜11を三稿まで回した時点で、**`njd_check.py` を三回通った原稿から、まだ事故が出ました。**
期待リストに無い語は素通りするので、リストを増やすだけでは追いつきません。
**新しく書いた行は、語単位で `njd()` に通して目視すること。**

### ① 助詞の「は・へ・を」が隣の語に飲まれる(新しく見つかった型)

助詞の「は」は**ワ**と読みます。名詞の直後の「は」がハと読まれていたら、
それは助詞として解析されていません。**隣の語に飲まれています。**

| 本文 | 実機 | 直し方 | 見つかった場所 |
|---|---|---|---|
| 手に職はね | テニショク・**ハネ** | 手に職は**ねえ** → ショク**ワ**ネー | 台本07(v1から3稿ぶん素通り) |
| 私はね、 | ワタシ・**ハネ** | 私は**ねえ**、 → ワタシ**ワ**ネー | 台本03(v3で発見) |

**「ね」を「ねえ」にすると助詞が独立します。**話し言葉としても自然なので、この直し方でよい。

`njd_check.py` の **⑦** がこの型を機械で拾います(名詞の直後の は/へ/を が助詞として
立っていない箇所)。**⑦に出たものは要修正件数に入ります。**

### ② 連濁

| 語 | 実機 | 直し方 |
|---|---|---|
| こんな話 | コンナ**バナシ** | 「こんなお話」/「次に見たい話を、」→ ハナシ |

`njd_check.py` の期待リストに **話:ハナシ** を入れました。

### ③ 分数の「分」が「ふん」になる

| 語 | 実機 | 対処 |
|---|---|---|
| 三分の一 / 三分の二 | **サンプン**ノイチ | 辞書登録が必須(台本11の相続の二行) |
| 五分の一 | **ゴフン**ノイチ | 「およそ二割」に言い換え(台本10) |

`njd_check.py` の **⑧** が語句単位で拾います。

### ③' 日付の「一日」が「いちにち」になる —— **辞書では直せない**

| 本文 | 実機 | 直し方 |
|---|---|---|
| 来月の一日 | ライゲツノ **イチニチ** | 「来月の、ついたち」→ ツイタチ |

## テロップ改行

`telop_wrap.py` が OpenJTalk のアクセント句境界を使って自動改行します。
アクセント句境界はほぼ文節境界なので、ここで折れば
「助詞だけが行頭に来る」「連体修飾が途中で切れる」事故が起きません。

```
python3 telop_wrap.py 台本.md --check   # 長すぎる文の検出
python3 telop_wrap.py 台本.md           # 改行済み台本を出力
```

### ルール(スマホ視聴前提)

| 項目 | 値 | 理由 |
|---|---|---|
| 1行 | **最大18文字** | スマホ横幅で2行が限界。19字を超えると文字が縮んで読めない |
| 1カード | **最大2行** | 3行は目線移動が増えて内容が入らない |
| カードの単位 | **1文** | 句点をまたいで1行にしない。読点でつながって見える |
| 折り位置の優先順位 | ①読点の直後 ②文節境界 ③強制 | 意味のかたまりを壊さない |
| 行頭禁止 | `、。」』）】!?…・ー` | 禁則処理 |

### カード分割のルール

- 文をカードで割らない(1文が2行に収まる限り、必ず同じカードに置く)
- 1行しか使わない短い文が続くときは、**2つまで同じカードに載せる**
  (「ふふ。」「そう」のような短い応酬がバラけるのを防ぐ)
- 3行以上必要な文だけ、例外的にカードをまたぐ

現行台本は **233カード / 342行 / 平均11.4字 / 最長18字 / 3行カード0**。

### 最重要:3行必要な文は「台本が悪い」

`--check` で【要短縮】と出たら、**改行を工夫するのではなく台本の文を短く書き直します**。
テロップ2行(36字)に収まらない文は、**そもそも耳でも理解しにくい**。
このチェッカーは改行ツールであると同時に、**文の長さの検査器**です。

現行台本は**全文が1文36字以内**に書き直してあり、`--check` は ✅ です。

## 台本を書くときの原則

| 原則 | 具体 |
|---|---|
| ①固有名詞は**漢字のまま+辞書登録** | カタカナ書きすると読みは直るが**アクセントが平板化して棒読みになる** |
| ②単独の漢字1〜2文字の和語に注意 | `方` `金` `器` `筋` — 送り仮名を足すか熟語にする |
| ③1文は36字以内 | テロップ2行に収まらない文は耳でも理解しにくい |
| ④語尾の `?` は**全角** | 疑問イントネーションが付く。半角 `?` は付かない |
| ⑤**推測で直さない。必ずツールに通す** | このマニュアルの過去版の失敗がそれです |

### 記号の扱い

`ｗ` `♡` `──` `……` は**すべて無音で、間(ま)にもなりません**(実機確認済み)。
本文に書いても効果ゼロです(タイトル・サムネにはOK)。

間は「、」「。」と行分割でのみ作れます。標準ポーズは 読点≒0.15秒 / 句点≒0.35秒。
それ以上の間が必要な箇所は、**その行を単独の音声ファイルにして編集で無音を挿入**します。

- 基本周波数が高く語尾が跳ねる設計で、**14分の重い話を聴かせる持久力がない**
